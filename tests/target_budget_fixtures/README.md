# Target-budget fixtures

Run `python3 tests/target_budget_test.py` from the repository root. The host runner
also executes these standard-library tests without requiring a target build.
CLI tests write only temporary files under ignored `build/` and clear inherited
`BUDGET_UPDATE`; checked-in budgets are never regenerated by these tests.

`loops.dis` is synthetic objdump-format text with placeholder instruction bytes.
It pins simple, nested and sibling loops, multiple branches to one head, the
nesting-depth cap, calls and divides, and zero cost outside loops. It also retains
the current approximation that an acyclic backward path can count as a loop.
The estimator is a static instruction heuristic, not a cycle or deadline proof.
Calls do not add their callees' costs.

`real_pi32v2.dis` is the donor's actual `dv_out` listing from firmware main
`19a7081`, built with JieLi Clang 4.0.1, `-Os` and selective minsize. Its expected
result is 40 instructions, 35 loop instructions, no loop divides/calls, cost 35.
Excerpt whitespace is normalized; instruction bytes and decoded text are preserved.

Parser tests preserve local labels, jump-table data, empty tracked functions,
untracked boundaries and functions in `.c1_text`. Within tracked functions,
address rows missing instruction bytes, empty text and explicit undecoded markers
(`.word`, `(bad)`, `unknown`, `unknown_instruction`) must fail. In particular, an
undecoded back edge must not silently erase a loop or permit a budget update.
This is bounded validation of objdump output, not a complete pi32v2 ISA validator.

CLI tests cover the 10% boundary, lower-cost notes, optional budgets, upstream's
one-core ISR fallback and dual-core selection, missing functions, default paths,
isolated updates and clean negative/nonnumeric budget failures. A zero-cost
function can update/read a zero budget; any positive cost exceeds that baseline
without dividing by zero. Malformed input is rejected before rewriting a budget.

Existing policies remain: missing disassembly skips, missing budgets warn and
pass, numeric extra entries are ignored, short budget lines are skipped, and any
nonempty `BUDGET_UPDATE` value (including `0`) rewrites. Updates omit optional
functions and bypass growth checks, but missing required functions still fail.
The parser hardening does not change `FUNCS`, `OPTIONAL`, `ONE_CORE`, loop-span
merging, weights, tolerance or checked-in budgets.
